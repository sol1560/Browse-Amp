# 验收要求

## M1
### Programmatic
- DMG SHA-256 与官方下载元数据一致；记录公开源码固定版本和许可证。
- 平台探测显示真实工具可用性，缺少设备不得显示已支持。
### UX
- 非界面阶段，不适用。

## M2
### Programmatic
- pnpm typecheck、pnpm test、pnpm build 通过。
- 会话访问隔离、控制权竞争、旧版本输入拒绝、结果未知不重放有测试。
- 真实 Chromium 能读取、点击、输入、截图并销毁。
### UX
- 后续 M5 经界面操作同一真实服务。

## M3
### Programmatic
- CLI/SDK/MCP 能创建、观察、操作和结束会话；未配置平台返回明确错误。
- 原生、E2B、Actions 必须实际运行才能标记验证。
### UX
- 错误显示可理解原因，不能伪造就绪设备。

## M4
### Programmatic
- 授权目标、到期、重复导入、跨用户读取、认证失效测试。
- 导入 cookie 后在受控网站读取到预期登录状态；秘密不出现在日志。
### UX
- 用户明确选择站点、目标和授权；取消不传输。

## M5
### Programmatic
- 构建通过；页面经真实服务完成创建、接管、销毁。
### UX
- 查看空列表、活动会话、不支持平台和错误状态截图；操作后检查 DOM。

## M6
### Programmatic
- 全局类型、测试和构建通过；记录实际通过数，不把未执行算通过。
- 按批准计划验证并发、登录泄漏、重试和权限；平台及性能未完成项明确记录。
### UX
- 提供已检查的代表截图；新用户有可执行的本地启动说明。

## M5R 跨设备与 Agent 验收
### Programmatic
- 两个独立客户端连接同一服务，一个控制设备、一个观察；接管后旧 Agent 请求被拒绝。
- 画面缩放后的触摸坐标映射到目标真实像素，不能把 2 倍屏幕点偏。
- Agent 用 SDK/MCP 操作受控测试页面，再读取实际结果断言成功，不仅检查请求状态码。
### UX
- 用手机尺寸与触控的浏览器检查查看、输入、交接流程；这是模拟触控测试，不宣称真实 iOS/Android 设备已测。
- 原生桌面无主机时单独记 BLOCKED，不用网页替代原生验收。
